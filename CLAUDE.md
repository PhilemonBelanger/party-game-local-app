# CLAUDE.md

Guidance for Claude Code working in this repo. See [README.md](README.md) for user-facing docs.

## What this is
Local Wi-Fi party games. Host screen (TV) + players on phones (same Wi-Fi, scan QR). All state
lives server-side; clients are thin. Three modes, chosen on the host home (`host:setmode`):
- **trivia** — multiple-choice + numeric ("closest wins") questions, images, timer, scoring, podium, sections.
- **gartic** — Gartic Phone / Telestrations: prompt → draw → guess chains, then host-driven reveal.
- **fibbage** — bluffing trivia: fill-in-the-blank prompt → players write fake answers → vote on the
  real one. Score for guessing the truth, fooling others, and thumbs-up. Host-driven, then podium.

Stack: **React + Vite** (frontend) · **Node + Express + Socket.IO** (backend). No DB — game
state is in-memory in the backend.

## Runs three ways
- **Docker dev** (hot reload): two containers — Vite `:5173`, backend `:3001`.
- **Prod single server**: backend serves the built UI **and** Socket.IO on one port (`3001`).
- **Single exe**: `trivia.exe` (Node SEA) bundling runtime + UI + default quiz. No install.

The frontend asks `GET /api/config` at runtime for the auto-detected LAN IP (QR/join URL).
No IP is baked at build time and the user never types one.

## Commands
Prefer the `justfile` recipes (shell set to `powershell.exe -ExecutionPolicy Bypass`):
- `just dev` — Docker dev stack via `start.ps1` (detects LAN IP → `.env` → compose up)
- `just up` / `just down` / `just logs` / `just restart`
- `just build-exe` — full pipeline → `trivia.exe`
- `just prod` — build + run bundled server (no Docker)
- `just firewall-open` / `just firewall-close`
- `just clean` — down + delete `build/`, `frontend/dist`, exe

Underlying npm scripts (root `package.json`): `build:web` → `bundle` → `build:server` → `start:prod`;
`build:exe` chains all + `make-sea`.

Build pipeline: `vite build` (single-file via vite-plugin-singlefile) → `scripts/bundle-html.mjs`
writes `backend/embedded.js` (UI string + default quiz) → `scripts/build-server.mjs` (esbuild →
`build/server.cjs`) → `scripts/make-sea.mjs` (Node SEA + postject → `trivia.exe`).

## Socket protocol
Client→server: `host:join`, `player:join`(name, cb→{id}), `host:start`, `player:answer`(value),
`host:next`, `host:reset`, `host:loadquiz`(quiz, cb→{ok}|{error}).
Server→client: `state` (full snapshot, broadcast on changes), `tick`(secondsRemaining) (per-second,
keeps base64 images out of the per-tick payload), `result` (private per-player right/wrong).

Phases: `lobby → question → reveal → … → podium`, plus `section` for section-header items.
Reveal is **always** host-triggered via `host:reveal` — never automatic. The Reveal button enables once
all connected players answer OR the timer hits 0. At 0 the server sets `state.timeUp` (answering locked,
`player:answer` rejected, players see "Time's up"); the round stays in `question` until the host reveals.
`host:next` advances after a reveal **or** past a section.
Privacy: a player's `choice` is only exposed in `state` during `reveal`; correctness is per-socket via `result`.

Players persist across disconnects: `players` is keyed by **lowercased name** (`nameKey`), with
`connected`/`socketId` fields; `socketToKey` maps live sockets → player. Rejoining with the same
name resumes the same player (score/answers kept). `allAnswered()` counts **connected** players only
(a dropped player won't stall the reveal). Client auto-rejoins on socket reconnect (App.jsx) and
re-entering the same name after a full reload also resumes. Host shows a roster (`PlayerPanel`,
top-right) — green = connected, red = disconnected.

Flow items live in `quiz.questions` and can be questions or section headers (`type:"section"`).
`gotoItem/advance` dispatch by type; sections set phase `section` (no timer, host continues).
`state` carries `questionNumber`/`totalQuestions` (sections excluded) and `lastItem` (for the host button label).

### Gartic mode (`backend/gartic.js`)
Client→server: `host:setmode`(mode), `gartic:submit`(content), `gartic:next` (host advance),
`gartic:reveal`(±1) (host nav). Server→client: `gartic:task` (private per-player: {round,type,prev,timeLimit}).
N players → N books; `assign[round][playerIdx] = bookIdx = (playerIdx + shift[round]) % N`, shift[0]=0 and
shift[1..N-1] shuffled (Latin square → each player touches each book once, never their own twice). Round 0 =
prompt, odd = draw, even = guess. Per-round timer: draw=`GARTIC_DRAW_TIME` (100s), prompt/guess=`GARTIC_GUESS_TIME`
(60s). Phases: `lobby → round → reveal`. Host advances each round (enabled when all connected submitted OR timer
hits 0). Auto-submit at timeout is done via **drafts**, not a racy post-timeout submit: the client emits
`gartic:draft`({round,content}) every 2s with its current canvas/text; on advance the server uses the
latest draft for any non-submitter (else a placeholder). Both `submit` and `draft` are round-tagged and
ignored if `round !== g.round` (prevents stale emits corrupting the next round). This is why letting the
timer run out still passes along the in-progress drawing — don't reintroduce a "submit on timeUp" path
(it races the host's instant Next and, worse, the canvas unmounts before capture). Reveal walks book-by-book, entry-by-entry; only the current entry is in
`state.reveal` (drawings are base64 — don't broadcast all books). Missing submissions are filled with
placeholders so chains stay intact. "Different source each round" is impossible at N=3 (only cyclic 3×3 squares).
Player set is snapshotted at start (`playerKeys`): mid-game joiners aren't in it → server sends them a
`{type:'spectator'}` task and excludes them from the gartic roster (they join the next game, no reshuffle).
Reconnect by name resumes the same slot; `taskFor` includes `done` (already-submitted) so they resume locked.
Reveal payload includes `seedPrompt` (book's initial prompt); `GarticReveal` shows `Fireworks` + a banner when a
guess equals it (case-insensitive). `DrawCanvas` has a rainbow swatch wrapping `<input type=color>` for custom colors.
Drawing process is recorded as vector ops (`DrawCanvas.getOps()`: `{t:'stroke',erase,color,size,pts}` /
`{t:'clear'}`, points throttled by distance) — sent alongside the PNG in submit/draft, stored on the draw
entry (`ops`), and replayed fast-forward (~4s) by `DrawReplay` in the reveal (falls back to the static PNG
when no ops). Compact (KB of coords, not MBs of snapshots); captures stroke order, erases, and clears.

### Fibbage mode (`backend/fibbage.js`)
Client→server: `host:setmode`('fibbage'), `fibbage:submit`({promptIndex,text}, cb→{ok}|{ok:false,reason})
(reason `truth`/`empty`/`stale`/`locked`), `fibbage:draft`({promptIndex,text}), `fibbage:vote`({promptIndex,
cardId,thumbId|null}), `fibbage:next` (host advance). Server→client: `fibbage:sync` (private, reconnect resume:
{phase,promptIndex,lie,votedCardId,thumbCardId} or {spectator:true}) and `result` (private per-player score
breakdown at reveal). 10 random prompts/game from the combined `normal`+`final` pool (env `FIBBAGE_PROMPTS`).
Per prompt phases: `answer → vote → reveal` (then game `podium`). Timers: `FIBBAGE_ANSWER_TIME` (60),
`FIBBAGE_VOTE_TIME` (100); reveal is untimed (host advances). **The real answer is never sent to clients before
reveal** — the truth check (`fibbage:submit` rejecting a lie that matches `answer`/`alternateSpellings`,
normalized) is server-side so curious clients can't read it. Drafts mirror gartic (heartbeat fills
non-submitters at timeout; skipped if a draft equals the truth). At answer→vote the server **coalesces**
identical lies (normalized: trim+collapse+lowercase) into one card, **pads back up to (players+1) cards
with distinct random `suggestions`** (authorless decoys — votes/thumbs on them score for nobody; this hides
coalescing/non-submitters from voters), adds the truth, shuffles once → stable `id`s; vote-phase
`state.cards` exposes only {id,text} (no authors/votes). Self-vote and self-thumb are
rejected server-side (and hidden client-side by matching the player's own lie text). Scoring (consts, env-
overridable): +150 truth guess, +100 per vote your lie drew (each author of a coalesced card), +50 to the
most-thumbed lie author(s) (ties all win). Cumulative `totalThumbs` drives the podium "most upvoted" mention.
`playerKeys` snapshot at start → mid-game joiners spectate, like gartic. Prompt rendering (`FibbagePrompt`):
`normal` prompts contain `<BLANK>`; `final` prompts have none (blank appended); HTML is stripped server-side
(`stripHtml` keeps the literal `<BLANK>` token — don't broaden the regex or it eats the blank).
**Bilingual (simultaneous EN/FR):** each prompt has `questionFR`/`answerFR`/`alternateSpellingsFR`/`suggestionsFR`
alongside the EN fields. The truth check accepts BOTH languages (and is accent-insensitive via `norm` NFD-folding),
so a FR player typing the FR answer is blocked even with an EN host. `state` carries both variants (`question`+
`questionFR`, `truth`+`truthFR`, cards `text`+`textFR`, `suggestions`+`suggestionsFR`); each client renders by its
own i18n `lang` (`useLangPick` in `FibbagePrompt.jsx`). Player lies are free text, shown as typed to everyone
(no cross-language coalescing); only truth + filler cards have distinct EN/FR text.

## Quiz JSON schema
```jsonc
{ "title": "…", "questions": [
  // multiple choice
  { "q": "…", "image"?: "data:…|url", "choices": ["A", {"text":"B","image":"…"}], "answer": 0, "points"?: 100 },
  // numeric — closest guess wins; ties all win
  { "q": "…", "type": "number", "answer": 412, "points"?: 100 },
  // section header — divider shown on all screens; host taps Continue. Not scored, not counted.
  { "type": "section", "title": "…", "image"?: "…", "description"?: "…" }
]}
```
`answer` = 0-based choice index, or the target number for `type:"number"`. `choices` 2–6, string or
`{text?,image?}`. Validation in `backend/server.js` (`validateQuiz`); creator GUI builds/imports/exports this.

## Conventions
- Caveman comms mode is active in this workspace (terse). Code/commits stay normal prose.
- Tunables via env: `PORT`, `TIME_LIMIT`, `BASE_POINTS`, `HOST_LAN_IP` (Docker override), `SKIP_FIREWALL`,
  `GARTIC_DRAW_TIME` (100), `GARTIC_GUESS_TIME` (60), `FIBBAGE_ANSWER_TIME` (60), `FIBBAGE_VOTE_TIME` (30),
  `FIBBAGE_PROMPTS` (10), `FIBBAGE_TRUTH_POINTS` (150), `FIBBAGE_VOTE_POINTS` (100), `FIBBAGE_THUMB_POINTS` (50),
  `FIBBAGE_THUMB_MIN` (2).
- Keep server authoritative; never trust client for scoring/answer visibility.

## Gotchas (learned the hard way)
- **`backend/embedded.js` is a committed DEV STUB** (`INDEX_HTML=null`). The build overwrites it
  with the 226KB UI; **restore the stub after building** so dev doesn't serve stale UI. (Don't
  `Read` it after a build — it's one giant line and blows the token limit; overwrite via shell/Write.)
- **Docker anon `node_modules` volume shadows the image.** After adding a dependency, recreate with
  `docker compose up --build --renew-anon-volumes` (start.ps1 already does this).
- **`trivia.exe` locks itself** while running → `make-sea` used to fail with EBUSY and silently leave the
  OLD exe (symptom: new features missing at runtime). `make-sea.mjs` now `taskkill`s it first. If a build
  ever looks stale, confirm no `trivia.exe` is running.
- **Git Bash mangles container paths** (`/app/x` → `C:/.../app/x`). Use `MSYS_NO_PATHCONV=1` for
  `docker compose exec`/`cp` with absolute container paths, or write test files into the bind-mounted dir.
- **Don't drop test `.mjs` into `/app`** — it's bind-mounted to `frontend/`, so files leak onto the host.
  Clean up host copies too.
- **`just`/npm on Windows**: needs `-ExecutionPolicy Bypass` (npm is a `.ps1` shim) — already set in the justfile.
- **LAN IP detection** (`detectLanIp` in server.js) works on the host (exe) but returns the container IP
  inside Docker → `HOST_LAN_IP` env overrides it for dev.

## Testing
No formal suite. Validate gameplay by scripting a socket.io-client (join → start → answer → reveal),
running it where deps exist (frontend container or host after `npm i`). Smoke-test the exe by running
it on a free port with `SKIP_FIREWALL=1` and curling `/api/config`, `/health`, `/`.
